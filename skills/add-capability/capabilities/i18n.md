# Add i18n (EN / MY)

Add UI internationalisation with plain Python dictionaries per language, a cookie-based switcher, and a template helper `t`. This mirrors the house pattern (`lang_en.py`, `lang_my.py`, `language.py`). Default languages English + Malay; add more dicts the same way.

> **Choose the right tool first.** The dict approach is simple and dependency-free — good for a fixed set of UI strings. But the **industry standard for Flask is Flask-Babel** (gettext `.po`/`.mo` files), and you should use it instead when you need any of: **pluralization** ("1 item" vs "3 items"), **locale-aware dates/numbers/currency**, `lazy_gettext` for module-level strings, or a **translator workflow** (Poedit/Weblate, `pybabel extract/update/compile`). If those apply, stop here and set up Flask-Babel — retrofitting dicts into gettext later is more work than starting with it. Use the dict approach below only for simple, developer-maintained string tables.

House-style discipline: functional, dicts + pure functions in `sources/`, imports at top, 4-space indent.

## Step 0: Preconditions

House-style Flask project with `templates/base.html` and an `inject_globals` context processor in the entrypoint (the scaffold has this). Clean git baseline.

## Step 2: `sources/language.py`

```python
# Language selection + lookup. Pure functions.
from flask import request

from sources.lang_en import PAGES as EN
from sources.lang_my import PAGES as MY

LANGUAGES = {"en": EN, "my": MY}
DEFAULT_LANG = "en"
COOKIE_NAME = "lang"


def current_lang():
    """Resolve the active language code from the cookie, default otherwise."""
    code = request.cookies.get(COOKIE_NAME, DEFAULT_LANG)
    return code if code in LANGUAGES else DEFAULT_LANG


def translations():
    """The dict for the active language, with English as key fallback."""
    active = LANGUAGES[current_lang()]
    if active is EN:
        return active
    merged = dict(EN)
    merged.update(active)   # active language overrides, EN fills gaps
    return merged
```

## Step 3: Wire into templates via the context processor

In the entrypoint, extend `inject_globals`:
```python
import sources.language as language

@app.context_processor
def inject_globals():
    ctx = {"current_year": datetime.now(timezone.utc).year}
    ctx.update(seo.default_meta())          # if the seo capability is present
    ctx["t"] = language.translations()
    ctx["lang"] = language.current_lang()
    return ctx
```

Use in templates: `{{ t.welcome }}`, `{{ t.items_title }}`. Set `<html lang="{{ lang }}">` in `base.html`.

## Step 4: Language switch route

```python
from flask import redirect, request, make_response
import sources.language as language

@app.route("/lang/<code>")
def set_language(code):
    if code not in language.LANGUAGES:
        code = language.DEFAULT_LANG
    resp = make_response(redirect(request.referrer or "/"))
    resp.set_cookie(language.COOKIE_NAME, code, max_age=60 * 60 * 24 * 365)
    return resp
```

Add a switcher to `_navbar.html`:
```html
<li class="nav-item"><a class="nav-link" href="{{ url_for('set_language', code='en') }}">EN</a></li>
<li class="nav-item"><a class="nav-link" href="{{ url_for('set_language', code='my') }}">MY</a></li>
```

## Step 5: Verify

- Boot the app; confirm default text is English.
- Visit `/lang/my`; confirm the cookie is set and UI text switches to Malay, and `<html lang="my">`.
- Add a key to `lang_en.py` but not `lang_my.py`; confirm the Malay page falls back to the English value (no crash / no missing key).

## Rules

- Every language file exposes the same `PAGES` keys. English is the fallback for any missing key.
- Keys live in `sources/lang_*.py`; no hardcoded UI strings in templates once i18n is in.
- Functional, imports at top, 4-space indent.
- Cookie-based selection (no per-URL locale prefixes) unless the user asks for SEO-friendly `/en/…` `/my/…` routing.
- This is UI-chrome translation only. Translating DB content (articles, product names) is a separate, data-model concern.
- If the project needs pluralization, locale-aware formatting, or a translator workflow, use **Flask-Babel** instead of dicts — don't extend the dicts to fake plurals/dates.
